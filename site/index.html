Probes are not parts.

Your Mac exposes 42 GPU die sensors and has 16 GPU cores. Nothing published says which sensor sits on which core — so SiliCool only calls something a core when the count matches what the OS reports, and labels the rest as probes rather than inventing hardware you don't have.

Install

Drag, open, approve.

Sensors work the second you open it. Fan control needs one approval, because writing to the SMC requires root.

1

Drag it to Applications

It has to run from there: macOS ties the approval to where the app lives, and SiliCool will tell you rather than let you approve something that cannot work.

2

Allow it once

macOS will say it can't verify the developer. Open System Settings › Privacy & Security, scroll to Security, and click Open Anyway. Once only — after that it opens normally.

3

Enable fan control

Sensors are already live. For the fans, press Enable Fan Control, then switch SiliCool on under System Settings › General › Login Items & Extensions.

Why does macOS warn about it?
SiliCool isn't notarized yet — Apple's automated malware scan requires a paid developer account, which this project doesn't have. The app is signed, so macOS can still tell you who built it and detect any tampering. The source is public and MIT licensed if you'd rather read it than trust it.
Safety

A pinned fan stays pinned. So every exit hands it back.

Fan settings outlive the process that made them. SiliCool treats that as its problem, not yours.

Force Quit cuts the line. Every other exit hands the fans back.

SIGKILL is the one signal no process can catch — the OS terminates it before it can react. If you force quit SiliCool while a fan is held, the hold persists because nothing remains to release it. To recover: reopen SiliCool and press Release, or restart your Mac. Every other exit path — quitting normally, logging out, sleeping, Ctrl-C, or a regular kill — returns the fans to automatic first.

Questions

Worth asking before installing a fan controller.

Can this damage my Mac?

SiliCool can only ask for speeds between the minimum and maximum the fan itself reports — 2317 and 7826 rpm on this machine. It cannot stop a fan the system wants running, and it cannot exceed the hardware's own ceiling. Thermal throttling is handled by your Mac's firmware and keeps working regardless. Running fans faster is the safe direction.

macOS says it can't verify the developer. Is that a problem?

It means SiliCool hasn't been through Apple's notarization service, which requires a paid Apple Developer account. It does not mean the app is unsigned or altered — it carries a valid Apple-issued signature, so macOS can identify the developer and will refuse to launch it if a single byte has been changed since it was built. To open it: System Settings › Privacy & Security › Open Anyway. If that makes you uncomfortable, don't install it — read the source and build it yourself instead.

Does it collect any data?

No. No analytics, no telemetry, no accounts, and no networking code at all — readings have no way to leave your Mac. See the privacy page.

Why does it need an admin approval?

Writing fan keys to the SMC requires root. Rather than running the whole app as root, SiliCool installs a small launchd daemon that does nothing but four privileged calls, and talks to it over XPC. Both ends verify each other's code signature, so nothing else on your Mac can drive your fans through it. Remove it from Settings at any time.

Does it work on Intel Macs?

Not yet. The sensor naming, the core-count checks and the manual-mode key all target Apple silicon. Intel Macs use different SMC keys for the same things, and would need their own testing before it would be trustworthy.

What happens if I delete the app?

Use Remove helper in Settings first — it returns the fans to automatic and unregisters the daemon. Deleting the app removes both, since the daemon lives inside the bundle, but the fans should be handed back before that happens.
